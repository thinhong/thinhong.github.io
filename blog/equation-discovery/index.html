  1. Methods come in two families: regression methods pick terms from a library that you propose, and symbolic regression builds the terms too.

  2. SINDy and global modelling are regression methods. SINDy returns one sparse model; global modelling returns many candidates and checks each one by simulation.

  3. A discovered equation is a hypothesis, not proof of a mechanism.

Today I learned about equation discovery from Quynh Anh’s talk (her code). You start with time series from a system, stored as a data matrix \(X\) with one row per time point and one column per variable. You want the differential equations that generated them: a system \(dX/dt = F(X)\).

Why bother? Differential equations can capture strongly nonlinear dynamics, and you can read every term in them. So equation discovery gives an interpretable model built from data, and it may point to mechanisms we did not know about.

The test case: the Lorenz system

To test a method, it helps to use a system whose equations we already know, so we can check the answer. The talk used the Lorenz system (Lorenz 1963):

\[ \begin{aligned} \frac{dx}{dt} &= \sigma (y - x) \\ \frac{dy}{dt} &= x (\rho - z) - y \\ \frac{dz}{dt} &= x y - \beta z \end{aligned} \]

with \(\sigma = 10\), \(\rho = 28\), \(\beta = 8/3\) and the starting point \((10, 10, 10)\). Multiplied out, the right-hand sides are \(10y - 10x\), \(28x - xz - y\) and \(xy - 2.667z\), so there are 7 terms. The problem is this: given only the three time series below, can a method find these 7 terms and their values?

// The right-hand side of an equation as text, for example "−9.998 x + 9.998 y". Weights are
// written with `digits` significant digits, or with `fixed` decimals as in the rows of weights.
// Weights smaller than `cut` are counted, not written.
function eqRhs(coef, { cut = 0, digits = 4, fixed = null } = {}) {
  const parts = [];
  let nTiny = 0;
  Array.from(coef).forEach((c, i) => {
    if (c === 0) return;
    if (Math.abs(c) < cut) return nTiny++;
    const num = fixed === null ? String(Number(Math.abs(c).toPrecision(digits))) : Math.abs(c).toFixed(fixed);
    const name = lib.labels[i] === "1" ? "" : lib.labels[i];
    const body = name && num === "1" ? name : name ? `${num} ${name}` : num;
    parts.push(parts.length ? ` ${c < 0 ? "−" : "+"} ${body}` : `${c < 0 ? "−" : ""}${body}`);
  });
  return { text: parts.join("") || "0", tiny: nTiny ? ` + ${nTiny} tiny ${nTiny === 1 ? "term" : "terms"}` : "" };
}

Two families of methods

The talk sorted the methods into two families. They differ in where the candidate terms come from: you propose them, or the algorithm builds them.

  • Regression-based methods start from a library of candidate terms that you propose, such as \(x\), \(xz\) or \(z^2\). A regression then selects the terms that stay and estimates their weights. SINDy and global modelling both work this way.
  • Symbolic regression, listed in the slides under genetic algorithms, builds the terms from variables, numbers and operations such as \(+\), \(\times\) and \(\sin\). In the version used by Schmidt and Lipson (2009), new equations are made by recombining and randomly changing earlier ones, and the ones that fit the data better are kept. No library is needed, but there are far more equations to search.

A 2023 review adds a third group that combines these ideas with neural networks (North, Wikle and Schliep 2023). Like the talk, this post sticks to regression.

The regression recipe

A regression-based method treats each derivative as the outcome and the candidate terms as the predictors. The slides use three steps, and the figures add a fourth to check the result:

  1. Compute the derivatives \(dX/dt\) from the data.
  2. Propose a library \(\Theta(X)\) of candidate terms: here all 10 polynomials in \(x\), \(y\) and \(z\) up to degree 2.
  3. Fit \(dX/dt \approx \Theta(X)\,\Xi\), where \(\Xi\) holds one weight per term and equation.
  4. Simulate the fitted system and compare it with the data.

Plain least squares gives 30 non-zero weights, but the true system has only 7 terms. The two methods differ in how they decide which weights should be zero.

Method 1: SINDy

SINDy (sparse identification of nonlinear dynamics; Brunton, Proctor and Kutz 2016) is built on the assumption that most weights in \(\Xi\) are exactly zero. It estimates \(\Xi\) with sequentially thresholded least squares:

  1. Fit all the terms by least squares.
  2. Set every weight with an absolute value below a threshold \(\lambda\) to zero.
  3. Refit with the terms that are left, and repeat until no weight is below \(\lambda\).

As in the talk, the derivatives come from a Savitzky-Golay filter (Savitzky and Golay 1964), and \(\lambda = 0.1\) as in her code.

Method 2: global modelling

Global modelling (Gouesbet and Letellier 1994) starts from the same regression, and the R package GPoM implements it (Mangiarotti et al. 2012; Mangiarotti and Huc 2019). The slides list three differences from SINDy:

  • It was designed for chaotic systems: GPoM simulates each candidate and checks whether its long-term behaviour (the attractor) matches the data.
  • It uses only polynomials, on the assumption that they can approximate the true system. You choose the degree (here 2, which gives the same 10 terms).
  • It has no threshold. GPoM fits the weights with the Gram-Schmidt process (a way to solve least squares). Then, in each equation, it removes the term whose removal increases the error the least, refits, and repeats, keeping every model along the way.

      plot.append(svg.node(), legend([["data", VIZ.faint], [`model ${c.id}`, good ? VIZ.ink : VIZ.grey]]));
      if (byTap && motion(1) > 0 && nV > 1) {
        const len = path.node().getTotalLength();
        path.attr("stroke-dasharray", `${len} ${len}`).attr("stroke-dashoffset", len)
          .transition().duration(motion(1400)).ease(d3.easeLinear).attr("stroke-dashoffset", 0)
          .on("end", () => path.attr("stroke-dasharray", null));
      }
      // on a narrow card the details sit under the grid: bring them into view after a tap
      if (byTap && !wide) {
        const box = side.getBoundingClientRect();
        if (box.top > innerHeight - 120) side.scrollIntoView({ block: "start", behavior: motion(1) > 0 ? "smooth" : "auto" });
      }
    }
    // simulate in slices of about 10 ms, so scrolling and tapping stay smooth
    const queue = thumbs.slice();
    const tick = () => {
      if (my !== job) return;
      const t0 = performance.now();
      while (queue.length && performance.now() - t0 < 10) {
        const t = queue.shift();
        t.fill(runOf(t.m));
      }
      const ready = cands.filter((m) => gpCache.runs.has(m.id)).map((m) => gpCache.runs.get(m.id));
      const nGood = ready.filter((r) => r.outcome === GOOD).length;
      summary.textContent = queue.length
        ? `simulating ${ready.length} of ${cands.length}`
        : `✓ ${nGood} of ${cands.length} reproduce the attractor`;
      if (queue.length) {
        setTimeout(tick, 0);
      } else {
        if (pick === null || !cands.some((m) => m.id === pick)) pick = (ready.find((r) => r.outcome === GOOD) || ready[0]).id;
        thumbs.forEach((t) => t.el.classList.toggle("on", t.m.id === pick));
        showDetail(false);
      }
    };
    tick();
  };
  watchWidth(root, (w) => { width = w; draw(); }, invalidation);
  return root;
}

GPoM labels each candidate as diverging, periodic or unclassified, and leaves the final choice to you (the ✓ in the figure follows my own simpler rule). Her slides show nine candidates that reproduce the attractor. Model 18 has exactly the true terms. Model 5 also works with only 6 terms, but its \(dy/dt\) has no \(y\) term. The pruning figure shows why: \(y\) adds little to \(dy/dt\), so removing it raises the fit error only to about 4%.

What is still hard

The Lorenz data here are clean and complete. Real data rarely are, and the slides list three problems:

  • Measurement noise makes the derivatives in step 1 unreliable. Smoothing the data first (for example with splines) can help, and so can weak or integral forms of SINDy, which integrate over time instead of differentiating the data (Schaeffer and McCalla 2017; Messenger and Bortz 2021).
  • Often only some variables are measured. The dynamics can sometimes be rebuilt from time-delayed copies (Takens 1981) or derivatives (Gouesbet and Letellier 1994) of one measured variable. Her notes add that this depends on how that variable is coupled to the unmeasured ones.
  • It is not always clear which measured variables belong in the model.

Where it could help

Quynh Anh suggested three possible uses in our field:

  • It could show how pathogens that circulate in the same population interact, or that they do not.
  • It could model how physiological signals change and detect when their dynamics shift.
  • It could infer unobserved states, such as the dynamics of vectors in vector-borne diseases.

Some studies have already tried this on epidemic data: SINDy on case reports of measles, chickenpox and rubella (Horrocks and Bauch 2020), and global modelling on the early COVID-19 epidemics (Mangiarotti et al. 2020).

Key things to remember

  • Equation discovery does not replace mechanistic models. A discovered equation is a hypothesis that needs validation and interpretation.
  • A regression method can only choose from the library you give it. If a true term is missing, no threshold can add it.
  • Several models can reproduce the same data, like models 5 and 18 here, so choosing among them needs other reasons: fewer terms, prediction tests, or knowledge of the system.
  • For a chaotic system, compare attractors, not exact paths.

To try these methods yourself, use PySINDy, a Python package for SINDy (de Silva et al. 2020), or GPoM, an R package for global modelling.

NoteR code (shortened from the talk)

The SINDy part (steps 1 to 3) was checked in R with a simple stand-in for drvSucc(), and it returns the exact Lorenz coefficients. The GPoM calls have not been run here; they use the same functions and settings as the talk’s code.

library(tidyverse)
library(deSolve)
library(GPoM)

# Simulate the Lorenz system (the talk used odin2 and dust2)
lorenz <- function(t, s, p) {
  with(as.list(c(s, p)), list(c(
    sigma * (y - x),
    x * (rho - z) - y,
    x * y - beta * z
  )))
}
lrz <- ode(
  y = c(x = 10, y = 10, z = 10), times = seq(0, 100, by = 0.001),
  func = lorenz, parms = c(sigma = 10, rho = 28, beta = 8 / 3)
) |>
  as.data.frame() |>
  rename(t = time)

# Step 1: derivatives with a Savitzky-Golay filter
deriv <- c("x", "y", "z") |>
  set_names() |>
  map(\(v) drvSucc(lrz$t, lrz[[v]], nDeriv = 1))
dxdt <- map(deriv, \(d) d$seriesDeriv[, 2])  # column 2 is the first derivative
t_keep <- deriv$x$tout                       # the filter drops points at each end

# Step 2: library of candidate terms (degree 2, with the constant as in the slides;
# the talk's SINDy code leaves the constant out and finds the same model)
theta <- lrz |>
  filter(t %in% t_keep) |>
  transmute(const = 1, x, y, z,
            x2 = x^2, xy = x * y, xz = x * z,
            y2 = y^2, yz = y * z, z2 = z^2)

# Step 3: sequentially thresholded least squares
stlsq <- function(theta, dxdt, lambda = 0.1, max_iter = 100) {
  theta <- as.matrix(theta)
  coefs <- rep(1, ncol(theta))  # start with every term active
  for (i in seq_len(max_iter)) {
    active <- which(coefs != 0)
    if (length(active) == 0) break
    fit <- qr.solve(theta[, active, drop = FALSE], dxdt)
    small <- abs(fit) < lambda
    coefs[active] <- if_else(small, 0, fit)
    if (!any(small)) break
  }
  set_names(coefs, colnames(theta))
}
sindy_coefs <- map(dxdt, \(d) stlsq(theta, d, lambda = 0.1))

# Step 4: simulate with GPoM::numicano().
# GPoM orders the 10 terms of a degree 2 model in 3 variables as
# 1, z, z^2, y, yz, y^2, x, xz, xy, x^2
gpom_order <- c("const", "z", "z2", "y", "yz", "y2", "x", "xz", "xy", "x2")
K <- sapply(sindy_coefs, \(k) k[gpom_order])
sim <- numicano(nVar = 3, dMax = 2, KL = K,
                onestep = 0.001, Istep = 1e5,
                v0 = c(10, 10, 10), method = "rk4")

# Global modelling with GPoM
gp <- gPoMo(as.matrix(lrz[, c("x", "y", "z")]), tin = lrz$t,
            dMax = 2, nS = c(1, 1, 1),
            nPmin = 6, nPmax = 11,
            IstepMin = 500, IstepMax = 5000,
            show = 0, verbose = FALSE)
table(gp$okMod)  # 0 = diverged, -1 = periodic, 1 = unclassified
visuEq(gp$models$mToTest5, nVar = 3, dMax = 2,
       substit = c("x", "y", "z"), approx = TRUE)
