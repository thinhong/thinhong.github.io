Today I learned about equation discovery from Quynh Anh’s presentation (her code). The goal is to recover differential equations from time series. The data matrix \(X\) goes in, with one row per time point and one column per variable. A system \(dX/dt = F(X)\) comes out.

Both methods in the talk, SINDy and global modelling, are regression methods. They follow the same plan: compute the derivatives, propose candidate terms, fit each derivative as a weighted sum of the terms, and check the result by simulation. They differ in how they choose the terms. The figures follow the order of her slides and run both methods in the browser on noise-free data.

The test case: the Lorenz system

\[ \begin{aligned} \frac{dx}{dt} &= \sigma (y - x) \\ \frac{dy}{dt} &= x (\rho - z) - y \\ \frac{dz}{dt} &= x y - \beta z \end{aligned} \]

with \(\sigma = 10\), \(\rho = 28\), \(\beta = 8/3\) and start \((10, 10, 10)\) (Lorenz 1963). Written out, the three equations have 7 terms. The question is whether each method can find these 7 terms from the three time series alone.

// Back, Next, Restart and Play for a figure that runs in steps.
// go(k, animate) draws step k; count() is the number of steps.
function stepper({ count, go, label = null, interval = 1300, invalidation }) {
  let k = 0, timer = null;
  const counter = html`<span class="viz-readout"></span>`;
  const back = button("◀ Back", () => to(k - 1));
  const next = button("Next ▶", () => to(k + 1));
  const restart = button("Restart", () => { stop(); to(0); });
  const play = button("▶ Play", () => (timer ? stop() : start()));
  function refresh() {
    const n = count();
    back.disabled = restart.disabled = k === 0;
    next.disabled = k >= n - 1;
    counter.textContent = label ? label(k) : `step ${k + 1} of ${n}`;
  }
  function to(j, animate = true) {
    k = Math.max(0, Math.min(count() - 1, j));
    go(k, animate);
    refresh();
  }
  function stop() {
    clearInterval(timer);
    timer = null;
    play.textContent = "▶ Play";
  }
  function start() {
    if (k >= count() - 1) to(0);
    play.textContent = "❚❚ Pause";
    timer = setInterval(() => (k >= count() - 1 ? stop() : to(k + 1)), interval);
  }
  if (invalidation) invalidation.then(stop);
  return { node: html`<div class="viz-btns">${back}${next}${restart}${play}</div>`, counter, to, stop, refresh, get k() { return k; } };
}

SINDy

SINDy (Brunton, Proctor and Kutz 2016) assumes that most weights in \(\Xi\) are exactly zero. It finds them with sequentially thresholded least squares: fit, set every weight smaller than a threshold \(\lambda\) to zero, refit with the terms that are left, and repeat until no weight is below \(\lambda\). Global modelling with GPoM

Global modelling (Gouesbet and Letellier 1994) starts from the same regression. The R package GPoM implements it (Mangiarotti et al. 2012; Mangiarotti and Huc 2019). Her slides describe it as the same general idea as SINDy, with a different way of choosing the terms:

  • There is no threshold. For each equation, GPoM removes one term at a time, the one whose removal increases the error the least, and keeps every model along the way.
  • Whole systems are judged by simulation. GPoM was designed with chaotic systems in mind, so it checks whether each candidate system reproduces the long-term behaviour of the data (the attractor).

It also assumes that polynomials can describe the system. You choose their degree (here 2, which gives the same 10 terms) and the range for the total number of terms in the system.

SINDy and GPoM side by side

SINDy GPoM
How terms leave Every weight smaller than \(\lambda\) is set to zero, then the model is refitted The term whose removal increases the error the least leaves, one at a time
What comes out One model per equation A sequence of models per equation, combined into many candidate systems
How a model is judged By its fit to the derivatives; simulation is an extra check By simulation: does it reproduce the attractor?
What you choose \(\lambda\) The polynomial degree, the range of total terms, and the final model

Key things to remember

  • The library must contain the true terms. No threshold can add a missing term.
  • Derivatives come first. These data are noise-free; with real data, noise in the derivatives is the main difficulty.
  • SINDy compares each weight with \(\lambda\). Refitting changes the weights that are left, so a later pass can remove more terms (the constant in \(dz/dt\) here).
  • Too small a \(\lambda\) keeps junk terms, and too large a \(\lambda\) removes true ones. Scan \(\lambda\) and look for a range where the chosen terms stay the same.
  • GPoM compares the terms with each other, keeps every model in the sequence, and judges whole systems by simulating them. You set the range for the total number of terms.
  • Several models can reproduce the same data. Model 5 has no \(y\) term in \(dy/dt\) and still reproduces the attractor. Choosing among such models needs other reasons: fewer terms, prediction tests, or knowledge of the system.
  • For a chaotic system, compare attractors, not exact paths.
  • A model that reproduces the data is a hypothesis about the mechanism, not proof of it.
  • GPoM is the R package for global modelling. PySINDy is a Python package for SINDy (de Silva et al. 2020).

The SINDy part (steps 1 to 3) was checked in R with a simple stand-in for drvSucc(), and it returns the exact Lorenz coefficients. The GPoM calls have not been run here; they use the same functions and settings as the talk’s code.

library(tidyverse)
library(deSolve)
library(GPoM)

# Simulate the Lorenz system (the talk used odin2 and dust2)
lorenz <- function(t, s, p) {
  with(as.list(c(s, p)), list(c(
    sigma * (y - x),
    x * (rho - z) - y,
    x * y - beta * z
  )))
}
lrz <- ode(
  y = c(x = 10, y = 10, z = 10), times = seq(0, 100, by = 0.001),
  func = lorenz, parms = c(sigma = 10, rho = 28, beta = 8 / 3)
) |>
  as.data.frame() |>
  rename(t = time)

# Step 1: derivatives with a Savitzky-Golay filter
deriv <- c("x", "y", "z") |>
  set_names() |>
  map(\(v) drvSucc(lrz$t, lrz[[v]], nDeriv = 1))
dxdt <- map(deriv, \(d) d$seriesDeriv[, 2])  # column 2 is the first derivative
t_keep <- deriv$x$tout                       # the filter drops points at each end

# Step 2: library of candidate terms (degree 2, with the constant as in the slides;
# the talk's SINDy code leaves the constant out and finds the same model)
theta <- lrz |>
  filter(t %in% t_keep) |>
  transmute(const = 1, x, y, z,
            x2 = x^2, xy = x * y, xz = x * z,
            y2 = y^2, yz = y * z, z2 = z^2)

# Step 3: sequentially thresholded least squares
stlsq <- function(theta, dxdt, lambda = 0.1, max_iter = 100) {
  theta <- as.matrix(theta)
  coefs <- rep(1, ncol(theta))  # start with every term active
  for (i in seq_len(max_iter)) {
    active <- which(coefs != 0)
    if (length(active) == 0) break
    fit <- qr.solve(theta[, active, drop = FALSE], dxdt)
    small <- abs(fit) < lambda
    coefs[active] <- if_else(small, 0, fit)
    if (!any(small)) break
  }
  set_names(coefs, colnames(theta))
}
sindy_coefs <- map(dxdt, \(d) stlsq(theta, d, lambda = 0.1))

# Step 4: simulate with GPoM::numicano().
# GPoM orders the 10 terms of a degree 2 model in 3 variables as
# 1, z, z^2, y, yz, y^2, x, xz, xy, x^2
gpom_order <- c("const", "z", "z2", "y", "yz", "y2", "x", "xz", "xy", "x2")
K <- sapply(sindy_coefs, \(k) k[gpom_order])
sim <- numicano(nVar = 3, dMax = 2, KL = K,
                onestep = 0.001, Istep = 1e5,
                v0 = c(10, 10, 10), method = "rk4")

# Global modelling with GPoM
gp <- gPoMo(as.matrix(lrz[, c("x", "y", "z")]), tin = lrz$t,
            dMax = 2, nS = c(1, 1, 1),
            nPmin = 6, nPmax = 11,
            IstepMin = 500, IstepMax = 5000,
            show = 0, verbose = FALSE)
table(gp$okMod)  # 0 = diverged, -1 = periodic, 1 = unclassified
visuEq(gp$models$mToTest5, nVar = 3, dMax = 2,
